Vision AI — How It Worksburnish.dev

The AI that
sees design.

A slide can pass every rule — correct colors, correct fonts, correct contrast — and still look bad. Cluttered layouts, poor hierarchy, walls of text. These are aesthetic judgments that require seeing the slide as a whole.

How It Works
Each slide is rendered as a thumbnail and sent to GPT-4o with a structured scoring rubric. The model evaluates 5 design dimensions and returns scores (1-10) plus plain-English reasoning.
DQS Formula
DQS = 40% Rules + 30% Vision AI + 30% Accessibility. Rules are the auditable foundation. Vision adds "does it look good?" Accessibility carries equal weight because compliance failures have legal consequences.
Why GPT-4o
Best-in-class multimodal layout understanding. Structured JSON output eliminates parsing failures. <3s per slide. $2.50/1M input tokens. Graceful degradation if unavailable.
VH
Visual Hierarchy
Is the most important content the most visually prominent?
2/10 — title same size as body, no focal point
9/10 — clear headline, key stat pops, supporting text recedes
WB
Whitespace Balance
Is breathing room well distributed — not too dense, not too sparse?
2/10 — wall-to-wall text, zero margins
9/10 — generous margins, content groups breathe
AD
Alignment Discipline
Do elements feel intentionally placed, snapped to a grid?
2/10 — shapes scattered randomly, inconsistent gutters
9/10 — everything snaps to grid, clean edges
CO
Consistency
Does this slide feel like it belongs in a cohesive deck?
2/10 — mixed styles, clashing fonts and weights
9/10 — unified palette, consistent type scale
ID
Info Density
Is the content load appropriate for a single presented slide?
2/10 — 300 words + 5 charts on one slide
9/10 — one idea, scannable in 3 seconds

Vision AI — DQS Scoreburnish.dev

Design Quality
Score.

Three signal sources, one composite number. Rules catch exact violations. Vision AI catches gestalt issues. Accessibility catches legal risk. They run in parallel, degrade independently, and combine into a single 0–100 score.

DQS = 40% × Rules + 30% × Vision + 30% × A11y
Why these weights?
Rules (40%) — auditable foundation, customers need to know exactly what failed.
Vision (30%) — the “does it look good?” layer that rules alone can’t capture.
Accessibility (30%) — compliance failures have legal consequences (EU A11y Act, ADA).
Worked Example
VH8/10 WB7/10 AD9/10 CO8/10 ID6/10
Vision Score = (8+7+9+8+6) / 5 × 10 = 76
Rule Score = 90    A11y Score = 85
DQS = 0.4×90 + 0.3×76 + 0.3×85 = 84.3
What GPT-4o Returns
{
  "visual_hierarchy": 8,
  "whitespace_balance": 7,
  "alignment_discipline": 9,
  "consistency": 8,
  "information_density": 6,
  "reasoning": "Strong headline
    hierarchy. Good whitespace around
    the chart. Subtitle 4px off-grid.
    Consistent palette. Slightly dense:
    4 bullets → reduce to 3."
}
The reasoning field is surfaced in the UI as plain-English feedback — the “design reviewer’s voice” that makes Burnish feel like having a senior designer on the team, not just a linter.

MVP Architectureburnish.dev

What we're
building.

A complete Upload–Check–Fix pipeline: PPTX or Google Slides in, brand-perfect deck out. 21 engineering tasks across 6 layers — deterministic rules + Vision AI + auto-correction.
Ingestion
PPTX + Google Slides → CSM
python-pptx parser + Google Slides API fetcher extract shapes, text, images into a typed Pydantic model. Both produce identical CSM. Stored in Cloudflare R2.
Rule Engine
6 Evaluators + Vision AI Scorer
Color (Delta-E CIELAB), typography, layout, accessibility (WCAG AA), content density, and image quality. GPT-4o vision scoring for subjective design assessment.
Corrections
Auto-Fix → Re-export or Write Back
Color swaps, font substitutions, contrast fixes, alignment snapping. Re-exported as .pptx or written back to Google Slides via batchUpdate API.
Backend
FastAPI + BullMQ Workers
Async SQLAlchemy + PostgreSQL with RLS. Clerk JWT auth. BullMQ workers for ingestion, checking, and correction. R2 storage for decks and thumbnails.
Frontend
Next.js 14 + Konva.js Previews
PPTX upload + Google Slides link import. Deck library, per-slide check results with bounding-box overlays, brand rule editor, side-by-side correction view.
Quality
Golden Deck Test Suite
Hand-crafted PPTX fixtures with known brand violations and accessibility failures. Full integration tests: upload → check → verify issues → correct → re-check.
